# Codebase Concerns

**Analysis Date:** 2026-04-10

## Tech Debt

**Monolithic SQL tool module:**
- Issue: Query execution, read-only validation, and all metadata SQL statements are concentrated in one large module.
- Files: `src/fde_sql_mcp/tools/databases.py:1`, `src/fde_sql_mcp/server.py:35`
- Impact: High change-coupling makes safe edits slower and increases regression risk when adding new tools.
- Fix approach: Split `src/fde_sql_mcp/tools/databases.py` into focused modules (query validation, shared execution, metadata groups) and keep `src/fde_sql_mcp/server.py` wrappers thin.

**Repository hygiene drift (tracked generated/debug artifacts):**
- Issue: Generated bytecode and local debug artifacts are tracked even though ignore rules exist.
- Files: `.gitignore:6`, `src/fde_sql_mcp/__pycache__/config.cpython-313.pyc`, `src/fde_sql_mcp/tools/__pycache__/databases.cpython-313.pyc`, `tmp/connect_ping.py:1`
- Impact: Noisy diffs, merge churn, and environment-specific artifacts in source control reduce reliability of reviews/releases.
- Fix approach: Remove tracked `__pycache__` and `tmp/` artifacts from git index, then enforce clean-tree checks in CI.

## Known Bugs

**Local config path mismatch with documented location:**
- Symptoms: A root-level `fde_sql_mcp.config.json` can be ignored at runtime, causing startup to fail unless env vars are set.
- Files: `src/fde_sql_mcp/config.py:9`, `README.md:51`
- Trigger: Running from repo root with config created per README instructions.
- Workaround: Set `SQL_SERVER_HOST` in environment or place config where `src/fde_sql_mcp/config.py` currently resolves it.

**`truncated` flag can be inaccurate at exact row limit:**
- Symptoms: Response can report `"truncated": true` when row count equals limit but there are no additional rows.
- Files: `src/fde_sql_mcp/tools/databases.py:146`
- Trigger: Queries returning exactly `row_limit` rows.
- Workaround: Re-run with a higher `max_rows` and compare counts.

## Security Considerations

**Certificate trust is permissive by default:**
- Risk: TLS encryption can still trust unverified certificates, weakening MITM protection.
- Files: `src/fde_sql_mcp/config.py:146`, `src/fde_sql_mcp/clients/sql.py:59`, `fde_sql_mcp.config.template.json:8`
- Current mitigation: `Encrypt=yes` is set in connection string (`src/fde_sql_mcp/clients/sql.py:57`).
- Recommendations: Default `sql_trust_server_certificate` to `false`, require explicit opt-in for trusted self-signed environments.

**Read-only guard can be fully disabled by configuration:**
- Risk: `run_readonly_query` can execute arbitrary SQL if `sql_enforce_readonly` is set false.
- Files: `src/fde_sql_mcp/config.py:169`, `src/fde_sql_mcp/tools/databases.py:75`, `src/fde_sql_mcp/tools/databases.py:139`
- Current mitigation: Default is enabled.
- Recommendations: Remove runtime disable in production builds or gate it behind explicit privileged mode.

**Connection-string injection surface through unvalidated database input:**
- Risk: User-provided `database` is interpolated directly into connection string and can include delimiter characters.
- Files: `src/fde_sql_mcp/server.py:42`, `src/fde_sql_mcp/clients/sql.py:55`, `src/fde_sql_mcp/clients/sql.py:68`
- Current mitigation: Not detected.
- Recommendations: Validate database names against a strict pattern or allowlist before building connection strings.

## Performance Bottlenecks

**Full in-memory fetch for all query paths:**
- Problem: All rows are materialized with `fetchall()` and converted to Python dicts.
- Files: `src/fde_sql_mcp/tools/databases.py:27`, `src/fde_sql_mcp/tools/databases.py:141`
- Cause: No streaming/pagination helpers in shared fetch layer.
- Improvement path: Use `fetchmany()` pagination and expose cursor/limit parameters for metadata tools.

**Per-request connection open/close overhead:**
- Problem: Every tool call opens a new pyodbc connection and tears it down immediately.
- Files: `src/fde_sql_mcp/tools/databases.py:14`, `src/fde_sql_mcp/clients/sql.py:70`, `src/fde_sql_mcp/clients/sql.py:76`
- Cause: No connection pooling strategy at application layer.
- Improvement path: Configure pyodbc pooling explicitly and/or introduce lightweight connection reuse per worker.

## Fragile Areas

**Regex-based SQL safety parser:**
- Files: `src/fde_sql_mcp/tools/databases.py:64`, `src/fde_sql_mcp/tools/databases.py:97`
- Why fragile: Lexical token checks are brittle for edge-case SQL syntax and can produce false positives/negatives.
- Safe modification: Isolate parser tests first, then replace with AST/sql-parser-backed validation or strict query templates.
- Test coverage: No automated tests detected for validator behavior (`tests/` not detected).

**Silent fallback when cursor timeout is unavailable:**
- Files: `src/fde_sql_mcp/tools/databases.py:22`, `src/fde_sql_mcp/tools/databases.py:136`
- Why fragile: Query timeout protection can disappear silently on some pyodbc builds, causing unbounded waits.
- Safe modification: Emit a warning/error path when timeout cannot be set, and fail closed in production profile.
- Test coverage: No tests detected for timeout behavior.

## Scaling Limits

**Thread-offload model without explicit backpressure:**
- Current capacity: Bounded by default `asyncio.to_thread` executor behavior; no application-level semaphore/queue is implemented.
- Limit: Burst traffic can queue long-running DB work and increase end-to-end latency.
- Scaling path: Add per-tool concurrency limits and request queueing metrics in `src/fde_sql_mcp/server.py`.

**Unbounded metadata payload sizes on list endpoints:**
- Current capacity: `sql_max_rows` applies only to `run_readonly_query`; list APIs return full result sets.
- Limit: Large schemas can produce large JSON payloads and memory spikes.
- Scaling path: Add `max_rows`/pagination to `list_*` tools in `src/fde_sql_mcp/server.py` and `src/fde_sql_mcp/tools/databases.py`.

## Dependencies at Risk

**Unpinned runtime dependencies:**
- Risk: `mcp[cli]` and `pyodbc` versions can drift between environments and break behavior unexpectedly.
- Impact: Inconsistent runtime behavior and harder incident triage.
- Migration plan: Pin dependency versions and commit a lockfile strategy compatible with `pyproject.toml` and `requirements.txt`.
- Files: `requirements.txt:1`, `requirements.txt:2`, `pyproject.toml:7`

**Legacy ODBC driver fallback path:**
- Risk: Fallback to `"SQL Server"` can target outdated/less secure driver stacks.
- Impact: Security posture and compatibility differ by host.
- Migration plan: Require modern driver versions and fail fast when only legacy drivers are present.
- Files: `src/fde_sql_mcp/clients/sql.py:21`
